# OpenCode evidence corpus

These are OpenCode recordings, not expected output generated by the reader.
`src/testing/fixtures.corpus.test.ts` validates the corpus; the reader and
composition tests compare observable behavior with these rows and bus events.

| Family | Capture and purpose | Redaction |
|---|---|---|
| `durable/*.json` (7 sessions) | Read-only census of an OpenCode database on 2026-09-10, captured with CLI 1.18.30; prompt/answer timing, tool parts, queued prompts, compaction, reverts, imported prefixes and descendant isolation | `scripts/lib/sanitize.mts` replaces free text with `<text:length>`, aliases private model/provider names, and preserves keys, enums, ids, timestamps and tool names. No credentials are recorded. |
| `live/*.json` (6 scenarios) | Native 1.18.30 TUI in a throwaway HOME/XDG/project; plain, permission once/reject, question reject, queued prompt and port-conflict scenarios; durable-before-bus and HTTP/PTY behavior | Synthetic prompts and sandbox files only; sandbox paths and ports normalized. HTTP records retain whether auth succeeded, never the password. |
| `schema.sql` | DDL of `session`, `message`, `part`, `event`, `event_sequence`, plus their indexes, used to reconstruct replay databases | Schema only, no user rows. |

`meta.recordedWith` is the CLI release observed at capture: 1.18.30 for this
corpus. It does **not** certify which binary wrote every historical row.
`meta.sessionVersion` (durable only) is the session row's creation/import stamp:
1.18.27 in three sessions, 1.18.29 in one, and `0.0.0-agent-code` in three.
`meta.opencodeVersion` retains the same old stamp for compatibility; do not use
it as a writer version. An imported session can later receive native writes.
`meta.schemaVersion` is `sha256:<hex>` of the exact `schema.sql` bytes, not an
OpenCode migration number. Updating the DDL requires reviewing the corpus.

The durable files contain `{meta, session, sequence, events, messages, parts}`;
the live files contain `{meta, scenario, opencodeVersion, sessionID, notes,
sse, durable, http, prompts, pty}` (plus capture details). Durable sequences
are per session; imported prefix messages appear only in the projection.
Post-commit user `summary` and compaction `tail_start_id` rewrites are allowed
and intentionally absent from previously emitted immutable entries.

The corpus contains SessionProcessor turns, not shell/subagent-command write
orders. `DurableReader.holds.system.test.ts` and
`OpencodeTerminalHeadless.durable.system.test.ts` document hand-authored cases
checked against the 1.18.30 embedded source. Do not relabel those as recordings.

To regenerate deliberately against another release:

1. Inspect that release's schema and refresh `schema.sql` from the five source
   tables and their indexes. Do not stamp an old DDL artifact as a new schema.
2. Capture durable evidence with `npm run census -- --db <path> --extract
   testing/fixtures/durable --recorded-with <observed-version>`. Optional
   `--sessions ses_a,ses_b` selects explicit sessions. The version comes from
   `opencode --version` in the capture environment, never `session.version`.
3. Capture live evidence with `NODE_PTY_PATH=<absolute-node-pty-path> npm run
   probe:live -- --binary <opencode-binary> --out testing/fixtures/live`.
   This is an explicit live operation, separate from deterministic checks.
4. Review redaction, metadata and changed shapes; run `npm run check` and
   `npm run test:coverage`. Update the census and accepted support version
   only after the compatibility review.
